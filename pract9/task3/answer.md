# Задание 3. Потокобезопасный реестр

## Почему `putIfAbsent`

Некорректный вариант «сначала `containsKey`, потом `put`» состоит из двух
операций. Между проверкой и вставкой другой поток может успеть создать сессию,
и оба вызова посчитают себя успешными.

`ConcurrentHashMap.putIfAbsent` выполняет проверку и вставку как одну атомарную
операцию. Возврат `null` означает, что сессия действительно создана этим
вызовом; возврат существующего значения — что id уже занят.

## Что защищено

- `create` не перезаписывает существующую сессию.
- `close` использует атомарный `remove`.
- `find` возвращает `Optional`, потому что отсутствие сессии — нормальный
  результат поиска, а не ошибка.
- `activeCount` вызывает `size()`. Для `ConcurrentHashMap` это приблизительное
  значение при одновременных изменениях; в демонстрации все потоки уже
  завершились, поэтому счётчик точен.

Внешний `synchronized` не нужен: конкурентная коллекция сама обеспечивает
атомарность отдельных операций. Составные операции из нескольких вызовов всё
равно требовали бы дополнительной синхронизации или `compute`.
