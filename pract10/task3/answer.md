# Задание 3. `allOf` с сохранением результатов

## Почему одного `allOf` мало

`CompletableFuture.allOf(futures)` возвращает `CompletableFuture<Void>`: он ждёт
завершения всех задач, но **не хранит их результаты**. Чтобы получить значения,
нужно сохранить исходные `CompletableFuture<Course>` и забрать результат из
каждого. Если обходить их в порядке постановки задач, порядок ответа совпадёт с
порядком `ids`, независимо от того, какая задача завершилась первой.

Типизация не теряется: список объявлен как
`List<CompletableFuture<Course>>`, поэтому `future.join()` сразу возвращает
`Course`, без приведений. `allOf` принимает массив `CompletableFuture<?>[]` — это
единственное место, где тип стирается.

`join()` удобнее `get()`: он не требует checked `InterruptedException` и бросает
`CompletionException` с исходной причиной.

## Политика 1: fail-fast по смыслу

«Всё или ошибка»: результат должен стать исключительным сразу после первой
неудачи, не дожидаясь остальных задач.

`allOf` сам по себе так не умеет: он завершается только когда завершились все
задачи. Поэтому для каждой задачи ставится `whenComplete`; при первой ошибке
общий `CompletableFuture<List<Course>>` завершается исключительно. Если ошибок
нет, счётчик `remaining` доходит до нуля, и результат собирается в исходном
порядке.

Важно: fail-fast здесь относится к **результату**, а не к выполнению. Остальные
задачи уже запущены и продолжают работать в фоне. Если их нужно остановить, надо
явно вызвать `cancel(true)` у каждого future.

```java
future.whenComplete((course, error) -> {
  if (error != null) {
    result.completeExceptionally(cause);
  } else if (remaining.decrementAndGet() == 0) {
    result.complete(order(futures));
  }
});
```

## Политика 2: частичный результат

«Всё, что успели»: ждём все задачи, успешные значения складываем в список,
неудачные — в список ошибок с идентификатором курса.

`allOf(...).handle((value, error) -> null).join()` нужен, чтобы дождаться всех
задач и не прервать ожидание на первой ошибке. После этого каждый future
разбирается отдельно: `join()` даёт курс или `CompletionException` с причиной.
Порядок успешных курсов остаётся исходным, ошибки перечислены отдельно.

## Результат

```text
allOf: elapsed=504ms
  0: JAVA-101 -> Основы Java
  1: DB-301 -> Базы данных
  2: WEB-401 -> Веб-разработка
fail-fast: elapsed=101ms, error=unknown course: NOPE-1
partial: elapsed=502ms, courses=2, errors=1
  ok: JAVA-101
  ok: WEB-401
  error: NOPE-1: unknown course: NOPE-1
```

`allOf` и частичный вариант ждут медленный `WEB-401` (около 500 мс). Fail-fast
возвращает ошибку через ~100 мс, как только завершился `NOPE-1`. Это разные
контракты: первый вариант сообщает «результата нет», второй — «вот что удалось,
вот что сломалось». Выбор зависит от того, может ли вызывающий код работать с
неполными данными.
